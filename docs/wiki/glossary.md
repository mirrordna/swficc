# Glossary

Last updated: 2026-07-04

## Canonical Version

The one dashboard version currently approved for development and validation. Current canonical URL:

https://dashboard.swfi.com/swficc/

## Live Requirements Document

The single coordinated requirements source owned by the SWFI requirements owner. Raw emails, chats, screenshots, and PDFs become implementation scope only after they are represented there or explicitly approved as bug fixes.

## Receipt

A machine-generated proof artifact under `output/` showing what was tested, when, against which URL or runtime, and with what result.

## Sendable

Ready to send to stakeholders for validation. This requires current receipts, no known blocking route/copy/data issues in the changed scope, and a clear validation summary.

## Full Universe Parity

Proof that the dashboard/backend mapping covers the relevant SWFI record universe, not only visible sample rows. This is not implied by page load success.

## Dashboard Mantra

The rule that dashboard sections should visualize, synthesize, and guide rather than merely dump tables.

## Side-Channel Scope

Any instruction that arrives outside the agreed requirements flow. Side-channel feedback can be captured, but should not be implemented until reconciled.

## Bad News First

The operating rule that blockers, failed checks, stale proof, missing scope, or partial verification must be stated before progress or success language.
